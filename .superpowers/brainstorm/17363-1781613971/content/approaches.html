3 Approaches cho Plugin Platform Architecture

Cùng mục tiêu — khác nhau ở cách core app và plugins giao tiếp.

A

🗂️ File-system Loader Đơn giản nhất

App scan thư mục /plugins, đọc manifest.json, load frontend + backend tự động. Git plugin = clone vào folder đó.

/plugins
  /crm      ← local
    manifest.json
    index.tsx
    /server
  /lms      ← git clone

Pros

  • Dễ debug
  • Transparent
  • Không cần DB cho registry

Cons

  • Restart để load plugin mới từ git
  • Khó track trạng thái enable/disable
B

🗃️ DB-backed Registry + Dynamic Loader ⭐ Recommended

Plugin files ở filesystem, nhưng metadata (enabled/disabled, config, version) lưu trong DB. App load theo danh sách từ DB. Git plugin cài qua Admin UI.

Plugin Files
/plugins/*
+
DB Registry
enabled, config
→
Plugin Loader
React.lazy + NestJS DynamicModule

Pros

  • Bật/tắt qua Admin UI không restart
  • Per-plugin config
  • Audit log

Cons

  • Phức tạp hơn A
  • Cần DB migration khi thêm field
C

🚌 Event Bus — Maximum Isolation

Core app và plugins KHÔNG import lẫn nhau. Giao tiếp hoàn toàn qua event bus. Plugin chạy trong isolated context.

  • Khó type-safe
  • Over-engineering cho giai đoạn đầu
